SiafuDB is a graph-native embedded database with a sync protocol built in. The complete architectural picture — fragment model, engine foundation, transport choices, and machine learning role — lives in the [01 — SiafuDB Architecture](/research/01-architecture) research document.

This page is the orientation map.

<Note>
  This page mixes what is released with design direction. Released today:
  the core engine with Cypher queries, the browser package with encrypted
  storage, and [Sync v0](/sync/v0). The Personal and Network fragment model,
  authority, transformations, and the GSPA and GSPN transports are design
  direction and are not built. SiafuDB is pre-release software.
</Note>

## Layers


| Layer               | Released in 0.4.0                                                                                  | Design direction                                  |
| ------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Access patterns     | Cypher queries. Key-value and document helpers in `siafudb-core`.                                  | Time-series and vector access patterns            |

## Fragment model

This section is design direction. Today, every database you open is a standalone local database. See [Fragments](/concepts/fragments).

Every SiafuDB instance is a **fragment** of a larger graph. In the design, two physically isolated instances run side by side on a user's device:

- **Personal.** Sovereign data. Encrypted with user keys. Never mixes with network data.
- **Network.** Honeycomb fragment, only present when the user opts in. Compromise reveals zero personal data.

In the design, each vertex carries an authority: **Authoritative** (source of truth here, push outward), **Referenced** (source of truth elsewhere, pull inward), or **Local** (no sync).

## Engine foundation

SiafuDB's engine is a fork of one open-source project, and its design draws on two more. The lineage is credited openly.

- **GrafeoDB** (Apache 2.0, Rust). The core engine is a fork of GrafeoDB 0.6.2. It lives in the repository under `engine/` and is published as the `siafudb-graph*` crates. SiafuDB builds it with the Cypher and GQL parsers. The examples on this site use Cypher.
- **KuzuDB research** (MIT, C++). An influence on the planned query execution work. No KuzuDB code is used.
- **ArcadeDB design** (Apache 2.0, Java). A design influence for the multi-model access patterns. No ArcadeDB code is used.

See [Engine Foundation](/research/01-architecture#the-engine-foundation) for the full picture.

## Transport

What ships is [Sync v0](/sync/v0). A device sends encrypted, signed changes to a relay over HTTPS, and the other devices pick them up.

The design has two transport modes. Neither is built:

- **GSPA**: Graph Sync Protocol with API. HTTP, gRPC, WebSocket, Kafka. Planned first.
- **GSPN**: Graph Sync Protocol with NTL. Neural signal propagation through NTL's learning network. Planned second.

See [GSPA](/sync/gspa) and [GSPN](/sync/gspn) for the design.
