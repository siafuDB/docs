---
title: "Your first sync"
description: "Run a relay on your machine and watch two browser windows keep the same data."
---

This guide runs a relay locally and syncs two browser profiles through it. It
takes about ten minutes, most of it compiling the relay. It uses
[sync v0](/sync/v0), which is tested in Chromium only.

You need the app from the [Quickstart](/guides/quickstart), a Rust toolchain
(1.99 or newer) and Node 24.

## 1. Start a relay

```sh
git clone https://github.com/siafuDB/siafudb-gsp
cd siafudb-gsp
cargo build --release -p gsp-relay
./target/release/gsp-relay --addr 127.0.0.1:8787 --in-memory
```

`--in-memory` keeps nothing when the relay stops, which is fine for a first
try. The relay prints a warning that says so.

<Note>
  Plain `http://` is accepted for `localhost` only. Any other relay must be
  reached over `https://`.
</Note>

## 2. Create a sync group on the first device

```ts
import { SiafuDB } from "@bundu/siafudb-web";

const db = await SiafuDB.open("notes");
await db.execute("CREATE (:Note {title: $t})", { t: "written on device one" });

const code = await db.sync.create({ relayUrl: "http://localhost:8787" });
console.log(code); // gsp0-… show it as text or as a QR code
```

Data that was already in the database is uploaded. From here on, writes go out
shortly after they commit.

## 3. Join from the second device

Open the app in a second browser profile, or a private window, so that it has
its own storage. Use the code from step 2:

```ts
const db = await SiafuDB.open("notes");
await db.sync.join({ relayUrl: "http://localhost:8787", code });

db.sync.onRemoteChange(async () => {
  const { rows } = await db.query("MATCH (n:Note) RETURN n.title");
  console.log(rows); // [["written on device one"]]
});
```

## 4. Watch it converge

Write on either side and the other receives it:

```ts
await db.execute("CREATE (:Note {title: $t})", { t: "written on device two" });
```

Then try the cases sync exists for:

- **Offline.** Switch one window offline in the browser's developer tools,
  write on both sides, and switch it back. Both end with every note.
- **Reload.** Reload a page. Sync resumes without being asked and nothing is
  duplicated.
- **The same note on both sides.** Change one property on each device while
  one is offline. The later write wins, per property.

## 5. See what the relay holds

Restart the relay with a data directory and repeat the steps:

```sh
./target/release/gsp-relay --addr 127.0.0.1:8787 --data-dir ./relay-data
grep -r "written on device" ./relay-data   # finds nothing
```

The relay stores only ciphertext. [What the relay sees](/sync/v0#what-the-relay-sees)
lists what it can and cannot learn.

## When something is wrong

`await db.sync.status()` says what the device thinks is going on: whether it
is connected, how many writes wait for upload, and whether one of the devices
has a wrong clock or was restored from a backup. The
[Sync API](/api-reference/sync) explains each field.
