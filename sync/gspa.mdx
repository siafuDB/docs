<Note>
  GSPA is design direction. None of the transports on this page is
  implemented, and no released package offers a GSPA API. What ships is [Sync
  v0](/sync/v0): the browser package talks to a relay over HTTPS and the relay
  stores only ciphertext. To use it, follow [Your first
  sync](/guides/first-sync).
</Note>

GSPA is the traditional transport mode for the Graph Sync Protocol. It uses **channels** — point-to-point pipes — with explicit connections and serialisation.

Transports the design plans for:

- **HTTP** — request/response for small mutation batches.
- **gRPC** — streaming, bidirectional, efficient for large deltas.
- **WebSocket** — long-lived push channels for near-real-time sync.
- **Kafka** — durable log for platform ingestion at scale.
- **Local TCP** — same-machine, cross-process.
- **In-process** — Rust channel for co-located instances.

## Where GSPA fits

GSPA is planned as the first of the two transport modes. It has no IPv6 requirement, no hardware neural engine, and no NTL dependency. The goal is that anything that already speaks HTTP or gRPC can reach a SiafuDB instance through GSPA.

You cannot use GSPA today. For sync that works now, use [Sync v0](/sync/v0).

## Shape

```
┌──────────────────────┐        GSPA channel          ┌──────────────────────┐
│  SiafuDB (fragment)  │ ───────────────────────────▶ │  SiafuDB (fragment)  │
│  Mutation emitter    │    (HTTP / gRPC / WS / Kafka) │  Mutation applier    │
│  + transform layer   │                              │                      │
└──────────────────────┘                              └──────────────────────┘
```

In the design, transformations are applied in the emitter before the mutation hits the wire. Transformations are not implemented.

## Endpoints

No GSPA endpoint exists yet. The research document sketches the planned surface. See [02 — Graph Sync Protocol §5](/research/02-graph-sync-protocol) for the endpoint-level spec.

## What GSPA will not do

GSPA does not learn. Routes are configured, not discovered. Weights are absent. Adaptive routing, hardware-accelerated forwarding and synapse-level transformations belong to the [GSPN](/sync/gspn) design.
