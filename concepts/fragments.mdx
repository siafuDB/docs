<Note>
  **Released:** every database you open with `siafudb-core` 0.4.0 or
  `@bundu/siafudb-web` 0.4.0 is a standalone local database. In Rust,
  `db.fragment().kind` is always `FragmentKind::Local`, and `open` takes no
  fragment argument. **Design direction:** Personal and Network fragments,
  their separate keys, and per-vertex authority. The `Fragment`,
  `FragmentKind` and `NodeAuthority` types exist in `siafudb-core`, but
  nothing stores or enforces them yet. SiafuDB is pre-release software.
</Note>

Every SiafuDB instance is a **fragment**. A fragment is a meaningful subset of a larger graph, with explicit knowledge of which parts it owns, which parts it references, and which parts stay local.

## Why fragments, not partitions

Sharded databases partition a single logical database across physical nodes. SiafuDB is the opposite: each instance is its own database, but it knows it's part of something bigger. Fragments can sync with each other, but they are never forced to.

This is the difference between a tree's leaves and a jigsaw's pieces. Leaves participate in the whole without needing to reconstitute it. Jigsaw pieces are meaningless until every piece is assembled.

## Physical separation: Personal vs Network

This is the design, not what ships. In the design, two completely isolated
fragments live on a user's device:

| Fragment     | Contains                                         | Encryption    | Sync              |
| ------------ | ------------------------------------------------ | ------------- | ----------------- |
| **Personal** | Messages, preferences, history, private AI state | User keys     | Personal pod only |
| **Network**  | Honeycomb-hosted platform data                   | Platform keys | Opt-in, tokenised |

The goal is that compromising the network fragment reveals no personal data,
because the two stores do not share a file, a key, or an index.

What you can do today is open two databases under different names or paths.
They are separate stores. The browser package encrypts each one at rest with
its own data key. `siafudb-core` does not encrypt the file it writes.

## Authority

In the design, each vertex in a fragment has an authority:

| Authority     | Meaning                   | Sync behaviour |
| ------------- | ------------------------- | -------------- |
| Authoritative | Source of truth here      | Push outward   |
| Referenced    | Source of truth elsewhere | Pull inward    |
| Local         | No sync                   | Stays local    |

In the design, authority is set at write time and enforced by the sync
engine. No released API sets or reads it. See [Authority](/concepts/authority) and [02 — Graph Sync Protocol](/research/02-graph-sync-protocol) for the full rules.
