A **mutation** is the atomic unit of graph change in SiafuDB. Every write produces one or more mutations. Mutations are what the Graph Sync Protocol signs, ships, and applies on the receiving device.

## Shape

On the wire, a mutation is a signed **op**. An op carries:

- A **content id**: the hash of the op's bytes. It is not a UUID, so any device can check it.
- An **author**: the identity that signed the op.
- A **fragment id**: the fragment the op belongs to.
- A **sequence number** and the id of the author's **previous op**. Together they form one chain per author, so a missing or reordered op is detectable.
- A **hybrid logical clock** value, which orders concurrent changes.
- **Dependencies**: the ops the writer had already applied.
- A **payload**: the change itself.
- One or more **signatures**, each tagged with its algorithm.

The planned payload operations are `vertex-create`, `vertex-update`, `vertex-delete`, `edge-create`, `edge-update`, and `edge-delete`. The payload schema is not defined in wire format v0.

See [Mutation format](/spec/mutation-format) for the fields and rules, and [Conflict resolution](/spec/conflict-resolution) for how concurrent mutations are ordered.

## Batches

Mutations can be grouped into a batch, which is signed as a unit. The batch signature covers the sender, the set of ops, and their order, so a relay cannot split or reorder a batch without detection. Each op in a batch keeps its own signatures.

## How mutations are captured

<Warning>
  Capture is not finished. Read this section before you rely on sync.
</Warning>

Today the engine records each write in an in-memory change log as the query text plus its bound parameters. This is enough to replay writes between two instances in one process. It is not a signed mutation, and the log does not survive a restart.

The target is structured capture: each write becomes a signed op with a defined payload, identical on every platform. Two sources are under evaluation:

- **Engine change data capture.** The engine can emit a change event per created, updated, or deleted vertex and edge.
- **A structured write API.** Writes go through typed calls that produce ops directly.

Which one becomes the supported path is undecided.

## Derived data

Some data leaves a fragment in a reduced form, for example with personal fields removed. A reduced mutation is a different object from the original: it has different bytes, a different id, and cannot carry the original signature. It is a separate, derived artefact, signed by the device that produced it.
